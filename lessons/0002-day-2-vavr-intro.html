Day 2: Enterprise Vavr (Try, Option, Tuple)

In high-throughput Spring Boot applications like Exgester, relying on standard Java exception handling (try/catch) causes massive thread context-switching overhead. Generating stack traces is extremely expensive. Vavr introduces monads that encapsulate absence (Option) and failure (Try) as data, completely bypassing the stack trace generation penalty when used correctly.

1. Option vs. Java Optional

Java's java.util.Optional is heavily restricted. It was designed primarily as a return type to prevent NullPointerExceptions. Vavr's Option is a true monad. It implements Iterable, meaning it can be seamlessly flattened inside collections, and it serializes perfectly.

The Jackson Serialization Problem

In Exgester, incoming JMS messages are parsed via Jackson. If you put a Java Optional as a field in a POJO, Jackson requires a specific Jdk8Module to deserialize it, and even then, it behaves unpredictably with null vs absent keys. Vavr Option integrates powerfully with vavr-jackson, accurately distinguishing between a null JSON value and an entirely missing JSON key.


import io.vavr.control.Option;

public record Counterparty(String lei, Option<String> bicCode) {}

// Safe chained lookups using flatMap
Option<String> bic = Option.of(trade.getCounterparty())
                           .flatMap(Counterparty::bicCode);

2. Try: Exceptional Control Flow

When interacting with the database or parsing complex XML/JSON, failures are expected. Throwing an exception unwinds the call stack, halting the pipeline. Try<T> captures computations that might fail, holding either a Success(T) or a Failure(Throwable).

Lifting Exceptions into Data

By wrapping a risky operation in Try, you maintain referential transparency. The function always returns a value, making it highly testable.


public Try<Trade> parsePayload(String rawJson) {
    // Try.of catches all non-fatal exceptions
    return Try.of(() -> objectMapper.readValue(rawJson, Trade.class));
}

Recovering Gracefully

In a large application, you don't just "fail"; you attempt fallbacks. Try.recover() or Try.recoverWith() allows you to specify exact exception types and provide alternate resolution paths.


Try<Trade> result = parsePayload(json)
    .recover(JsonParseException.class, e -> {
        log.warn("Malformed JSON. Attempting legacy parser...");
        return legacyParser.parse(json); 
    })
    .recover(IllegalArgumentException.class, e -> {
        log.error("Missing mandatory fields.");
        throw e; // We can explicitly re-throw if it's unrecoverable
    });

3. Type-Safe Tuples in Routing

Often, a pipeline step needs to calculate a value and pass *both* the original trade and the new value downstream. Java forces you to either create a temporary DTO class or mutate the original object. Both are bad. Vavr Tuple solves this.


// A function that returns the Trade alongside its calculated Regulatory Region
public Tuple2<Trade, String> determineRegion(Trade trade) {
    String region = routingEngine.getRegion(trade.lei());
    return Tuple.of(trade, region);
}

// Downstream usage
Tuple2<Trade, String> context = determineRegion(trade);

// We can map specific elements of the tuple without unpacking it!
Tuple2<Trade, String> mappedContext = context.map2(region -> "REGION_" + region);
