Day 2: Introduction to Vavr

The Exgester reporting engine leverages functional programming concepts to ensure robustness. Native Java provides some tools (like java.util.Optional and Streams), but they fall short for building robust pipelines. Enter Vavr, a functional library for Java 11+.

Today, we introduce three essential Vavr types: Option, Try, and Tuple.

Why Vavr?

Vavr brings pure functional data structures and control structures (like Scala or Haskell) to Java. It allows us to treat exceptions and nulls as just another type of data, which is essential for Railway-Oriented Programming (ROP).

1. Vavr Option vs Java Optional

Vavr's Option is an object container which may or may not contain a value. Unlike Java's Optional, it implements Iterable and integrates seamlessly with Vavr collections, plus it provides better monadic operations.


// Creating an Option
Option<String> maybeLei = Option.of(trade.counterpartyLei());

// Providing a default fallback
String lei = maybeLei.getOrElse("UNKNOWN_LEI");

// Transforming values safely
Option<Integer> leiLength = maybeLei.map(String::length);

2. Try: Exceptional Handling without try/catch

In data pipelines, throwing exceptions breaks the flow. Try encapsulates a computation that might result in an exception. It has two states: Success and Failure.


// ❌ BAD: Breaking the pipeline with exceptions
public String parseJson(String json) {
    try {
        return objectMapper.readTree(json).get("tradeId").asText();
    } catch (Exception e) {
        throw new RuntimeException("Invalid JSON", e);
    }
}

// ✅ GOOD: Returning a Try
public Try<String> parseJsonSafe(String json) {
    return Try.of(() -> objectMapper.readTree(json).get("tradeId").asText());
}

You can then recover from failures cleanly:


String safeTradeId = parseJsonSafe(rawPayload)
    .recover(JsonParseException.class, "DEFAULT_ID")
    .getOrElse("UNKNOWN_ID");

3. Tuples: Returning Multiple Values

Often, a function needs to return multiple values. Creating a Java 17 record for every minor grouping is overkill. Vavr provides Tuple1 to Tuple8.


// Grouping related items instantly
Tuple2<String, Double> tradeSummary = Tuple.of(trade.tradeId(), trade.notional());

// Accessing values
String id = tradeSummary._1;
Double not = tradeSummary._2;

// Mapping over a tuple
Tuple2<String, Double> updated = tradeSummary.map2(n -> n * 1.5);
