Day 2: Generics — Reading Exgester's Type Signatures

🎯 Week 1: Java Foundations ⏱️ 60 minutes

Exgester relies heavily on Java Generics to build its reusable decision pipeline. You will frequently encounter signatures like Either<Rejection, TradeContext> or DecisionStep<I, O>.

Key Concepts

  • Type Parameters: e.g., <T> allows classes and methods to operate on objects of various types while providing compile-time type safety.
  • Bounded Wildcards:
    • ? extends T (Upper Bound): Represents an unknown type that is a subtype of T or T itself. Used for reading/producing values (PECS: Producer Extends, Consumer Super).
    • ? super T (Lower Bound): Represents an unknown type that is a supertype of T or T itself. Used for writing/consuming values.
  • Type Erasure: Java removes generic type information at compile time. List<String> and List<Integer> both become just List at runtime.
The PECS Rule

Producer Extends, Consumer Super.
If your method needs a collection to read from, use ? extends T. If it needs a collection to add to, use ? super T.

Your Task

You will build a generic DecisionStep<I, O> interface and wire up a multi-step pipeline using generic types.
