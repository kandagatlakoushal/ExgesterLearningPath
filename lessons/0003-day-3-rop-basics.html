Day 3: Railway-Oriented Programming (ROP)

Welcome to the most important architectural pattern in the Exgester module: Railway-Oriented Programming (ROP). This concept dictates how all trade events flow through our decision engines.

When processing a trade, we must execute a series of validations: Is the trade valid JSON? Does it have a known counterparty? Is the notional amount within limits? In traditional imperative programming, this results in deeply nested if-else blocks or excessive exception throwing. ROP solves this elegantly.

1. The Two-Track Model

Imagine a railway switch. A train (our Trade Event) enters the switch. If everything is fine, it continues on the Happy Track (Green). If something goes wrong, it gets switched to the Error Track (Red).

Once a train is on the Error Track, it bypasses all subsequent "Happy Track" switches and goes straight to the end of the line (e.g., an error log or rejection queue).

2. Enter Vavr Either<L, R>

In Vavr, the Either type represents a value of one of two possible types: a Left (by convention, the error/rejection track) or a Right (the success/happy track).


import io.vavr.control.Either;

// A successful validation
Either<String, Trade> success = Either.right(new Trade("T1", "EMIR"));

// A failed validation
Either<String, Trade> failure = Either.left("Trade missing LEI code");

3. Why is this powerful?

Because Either is "Right-biased", you can chain operations on it. If an Either is currently a Right, the operation executes. If it is already a Left, the operation is skipped.


public Either<String, Trade> validateNotional(Trade trade) {
    if (trade.notional() <= 0) {
        return Either.left("Invalid Notional");
    }
    return Either.right(trade);
}

// Processing a Right
Either<String, Trade> goodTrade = Either.<String, Trade>right(new Trade("T1", 100.0));
goodTrade.flatMap(this::validateNotional); // Returns Right(Trade)

// Processing a Left (Short-circuiting!)
Either<String, Trade> badTrade = Either.<String, Trade>right(new Trade("T2", -50.0));
badTrade.flatMap(this::validateNotional); // Returns Left("Invalid Notional")
The FlatMap Magic

flatMap is the switch on the railway. It takes the current Right value, runs it through a function that returns an Either, and flattens the result. If the function returns a Left, the train has been moved to the Error Track.
