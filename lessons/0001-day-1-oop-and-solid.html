Day 1: OOP & SOLID in 60 Minutes

🎯 Week 1: Java Foundations ⏱️ 60 minutes

Before diving into the functional world of Vavr and Railway-Oriented Programming, we need to ensure our Java fundamentals are rock solid. Exgester's architecture is heavily based on SOLID principles, specifically the Single Responsibility Principle (SRP) and the Open-Closed Principle (OCP).

How Exgester uses SOLID

In Exgester, a DecisionStep does exactly one thing (SRP): validate formatting, OR check thresholds, OR determine the region. When a new regulatory rule is added, we don't modify existing code; we add a new step or strategy (OCP). This makes the massive codebase maintainable.

The Core Principles

  • Single Responsibility: A class should have one, and only one, reason to change.
  • Open-Closed: Software entities should be open for extension, but closed for modification.
  • Liskov Substitution: Subtypes must be substitutable for their base types.
  • Interface Segregation: Many client-specific interfaces are better than one general-purpose interface.
  • Dependency Inversion: Depend upon abstractions, not concretions.
