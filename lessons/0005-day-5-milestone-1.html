Milestone 1: Pure Java Decision Engine

Congratulations on reaching the end of Week 1! You've learned about deep immutability via Java 17 Records, handling side effects with Vavr's Try, and constructing scalable, fast-failing validation pipelines using Either.

Before we move into Spring Boot, dependency injection, and messaging next week, we must solidify the core domain. The Exgester engine is fundamentally a pure function that takes a raw Trade JSON and outputs either a valid, enriched Trade or a specific Rejection. That logic should not require a framework.

1. The Architecture of the Engine

Your goal is to build a self-contained, highly testable engine package.

The "Hexagonal" Core

In a Hexagonal Architecture (Ports and Adapters), the center of your application contains pure business rules with NO dependencies on external frameworks like Spring Data, JMS, or web servers. You are building this pure center today.

The Entry Point

You will create an ExgesterEngine class. It exposes a single public method:


public void process(String rawJsonMessage);

Inside this method, you will chain together the parser and the validation strategies. Finally, you will use .fold() to simulate the routing (printing the result to the console for now).

2. Strategy Pattern for Regulatory Rules

The core complexity of Exgester is that a trade must be reported to different regulatory bodies depending on its Region (e.g., EMIR for Europe, ASIC for Australia). You cannot hardcode these rules into a massive if/else block.

You will implement an interface RegulatoryStrategy:


public interface RegulatoryStrategy {
    boolean supports(String region);
    Either<Rejection, NewTrade> applyRules(NewTrade trade);
}

Then, create implementations like EmirStrategy and AsicStrategy. The engine will evaluate the trade's region, pick the correct strategy, and apply its rules.

3. Testing the Pipeline

Because your code is purely functional, testing it is a breeze. You don't need mocking frameworks like Mockito yet. You simply pass in a JSON string, and assert the output.


// A sample JUnit 5 test (Optional but highly recommended)
@Test

    String badJson = "{ \"tradeId\": \"123\", \"region\": \"EMIR\" }";

    // Assert the output is a Rejection with code "MISSING_LEI"
}
